## UI regression sweep

Search over all of `e2e/` for the strings changed (header, footer and dashboard menu entries): the specs that assert menu contents (`staff-multi-role`, `csr-uat`) only check named items and are unaffected by the two new entries. The full `regression` project was run locally on the dev server (767 tests: 654 passed, 73 failed), then the failing files were re-run serially against a production build on a clean database: 183 passed, 36 failed, and a clean `develop` checkout fails the same eight files with identical counts. The sweep found one real regression caused by this bundle: `whatsapp-support-thread` AC1 sends "A different question about my booking", and the first version of the booking intent answered it with the Book link instead of opening a ticket. It is fixed (a message about an existing booking, or a question or a change, stays support text) and the spec now passes.
